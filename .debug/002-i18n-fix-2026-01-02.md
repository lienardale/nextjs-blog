# i18n Translation Fix for Next.js 16

## Problem
After upgrading to Next.js 16, the `next-translate` i18n library stopped working. Translation keys like `categ0`, `metaTitle`, `intro`, etc. were appearing as literal strings instead of their translated values.

### Expected Behavior
- `t('categ0')` → "Expérience" (in French)
- `t('metaTitle')` → "alienard 🥖"
- `t('title')` → "Bienvenue sur mon site !" (in French)

### Actual Behavior (Before Fix)
- `t('categ0')` → "categ0" (literal string)
- `t('metaTitle')` → "metaTitle" (literal string)
- `t('title')` → "title" (literal string)

## Root Cause
Next.js 16 uses **Turbopack** as the default bundler instead of webpack. However, `next-translate-plugin` version 2.6.2 only supports webpack configuration and doesn't yet work with Turbopack.

## Solution
Force webpack mode by updating the npm scripts in `package.json`:

```json
{
  "scripts": {
    "dev": "next dev --webpack",
    "build": "next build --webpack",
    "start": "next start"
  }
}
```

## Verification
After applying the fix:

1. **Development server**: `npm run dev` now runs with webpack mode
2. **Build output** shows proper translation compilation:
   ```
   next-translate - compiled page: / - locale: en - namespaces: common
   next-translate - compiled page: / - locale: fr - namespaces: common
   next-translate - compiled page: / - locale: de - namespaces: common
   next-translate - compiled page: / - locale: es - namespaces: common
   ```
3. **Runtime**: All translations work correctly across all languages (en, fr, de, es)

## Testing Results

## Performance Impact
Using webpack instead of Turbopack means:
- **Development**: Slightly slower hot module replacement (HMR)
- **Production builds**: Similar performance (both are optimized)
- **Runtime**: No difference (this only affects build time)

## Future Migration
When `next-translate` adds full Turbopack support:
1. Remove the `--webpack` flags from package.json scripts
2. Test that translations still work
3. Enjoy faster development builds with Turbopack!

Monitor the next-translate repository for Turbopack support updates:
- GitHub: https://github.com/aralroca/next-translate
- npm: https://www.npmjs.com/package/next-translate

## Alternative Solutions Considered

### 1. Downgrade Next.js (Not Recommended)
- Would miss out on Next.js 16 features and React 19 benefits
- Security updates and bug fixes in newer versions

### 2. Switch to next-i18next (Not Chosen)
- Would require significant code refactoring
- Different API and configuration
- Migration effort outweighs benefits for this project size

### 3. Use Canary Version of next-translate (Risky)
- Version 3.0.0-canary.5 exists but is unstable
- May introduce unexpected bugs
- Not recommended for production

### 4. Force webpack mode (CHOSEN) ✅
- Minimal configuration change
- No code refactoring needed
- Stable and reliable
- Easy to revert when Turbopack support is added
